# ADR-0001. Доставка кода TimeCapsule на EC2

**Статус:** принято для ЛР2.

## Контекст

TimeCapsule работает на одном EC2. PostgreSQL, сессии и вложения локальны. Версию приложения нужно обновлять и возвращать к рабочему состоянию, сохраняя данные и настройки.

## Варианты

| Вариант | Преимущества | Ограничения |
| --- | --- | --- |
| Копирование через SCP | Доступно через SSH и подходит для нескольких статических файлов | Нужно вручную выбирать файлы, проверять целостность версии и хранить предыдущую копию |
| Ручной деплой через Git | Git показывает точный коммит, а `git pull --ff-only` останавливается при расхождении истории | Установка зависимостей и перезагрузка PHP-FPM остаются ручными шагами |
| Git и скрипт, запускаемый по SSH | Одна повторяемая последовательность с проверкой ошибок и выводом версии | Обновление файлов на одном сервере происходит на месте. Сбой после обновления Git требует восстановления |

## Решение

Вариант B. Сервер получает код из публичного репозитория по HTTPS. По SSH запускается `deploy.sh`, который выполняет fast-forward, устанавливает зависимости Composer и перечитывает конфигурацию PHP-FPM. Для отката используется `git revert` в репозитории и повторный деплой.

## Последствия

Публичный репозиторий позволяет серверу скачивать код без токена. Файл `.env`, вложения и файлы сессий остаются на EC2, а PostgreSQL использует собственный каталог данных. Скрипт не изменяет схему автоматически. На одном сервере возможна кратковременная ошибка в процессе обновления, особенно если установка зависимостей не завершилась. Для следующего шага подходят проверки до деплоя и атомарное переключение версий после успешной проверки.
